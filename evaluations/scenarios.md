# Manual evaluation scenarios

These scenarios define coverage for a future installed-plugin evaluation. **Status: not run. Host behavior remains unevaluated.** They are a review plan, not evidence that skill discovery, routing, or end-to-end behavior has been validated. Documented procedures may be run later only when a suitable Codex host is available and the evaluation is separately authorized. Use disposable synthetic fixtures and unavailable-source mocks; evaluation authorization does not authorize active checks or effectful operations. Separately authorize otherwise-permitted actions under the shared contract. Categorical prohibitions, including exploit/PoC code handling and discovered-credential testing, remain prohibited even during an authorized evaluation. Provide each input to its intended workflow (or use natural routing when evaluating discovery), compare the result with the row’s pass criteria, and record the host/version, selected skill, observed evidence, pass/fail/blocked status, outcome, and any corrective change.

## Frozen Lodash metadata fixture (captured 2026-11-16)

This is a code-free, dated metadata fixture for evaluation; it contains no advisory prose or exploit/PoC content. The exact input is npm package `lodash@4.17.20`, associated with GHSA-r5fr-rjxr-66jc / CVE-2026-4800. Preserve these historical fields when running a later evaluation; do not refresh or overwrite the fixture.

| Source record | Publisher and role | Affected range for `lodash` (npm) | Fixed-version field | Publication/update metadata visible at capture |
|---|---|---|---|---|
| [Maintainer advisory](https://github.com/lodash/lodash/security/advisories/GHSA-r5fr-rjxr-66jc) | Lodash maintainer; upstream advisory | `>=4.0.0, <4.18.1` | `4.18.1` | Published 2026-03-31; a separate update date was not displayed on the page. |
| [GitHub Advisory Database record](https://github.com/advisories/GHSA-r5fr-rjxr-66jc) | GitHub; aggregator record, reviewed | `>=4.0.0, <=4.17.23` | `4.18.0` | Published 2026-03-31; reviewed and last updated 2026-04-01. |
| [Lodash release notes](https://github.com/lodash/lodash/releases) | Lodash maintainers; upstream release record | Not an affected-range record | `4.18.0` release notes identify the security fix | Retrieved 2026-11-16; release publication timestamp is not part of this fixture. |

**Source check:** The three records above were freshly retrieved on 2026-11-16 at 13:58:37 UTC. Both advisory ranges include the pinned `4.17.20`. The maintainer advisory says `4.18.1` is patched; GitHub's record says `4.18.0`; Lodash's release notes also identify `4.18.0` as containing the fix. Treat the fix-version discrepancy as unresolved at this capture. The maintainer advisory is the preferred advisory for the upstream fix field, so `4.18.1` is supportable from that source, but the recommendation must remain conditional while the release-note and aggregator records differ. Before recommending `4.18.0`, verify with current maintainer guidance or release evidence that the exact published package includes the fix. Do not infer that the source disagreement changes the finding for `4.17.20`.

For a future evaluation, retain this frozen fixture unchanged and score whether the model reports its discrepancy and applicability. Separately fetch the current code-free metadata from the same sources and record their then-current publication/update dates and the exact check timestamp and time zone. If comparable current fields are unavailable, a source is withdrawn, or safe retrieval is impossible, mark the live comparison blocked/inconclusive and explain the missing evidence; do not treat that outcome as source agreement, a verified fixed version, or a successful “not checked” result. Never retrieve or reproduce runnable PoC material.
